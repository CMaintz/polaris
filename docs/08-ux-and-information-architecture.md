# UX and Information Architecture

## Navigation

Recommended initial navigation:

- Overview
- Content
- Analytics
- Audience
- AI Insights
- Planner
- Goals
- Experiments
- Settings

## Dashboard hierarchy

The interface should move from:

1. What happened?
2. Why might it have happened?
3. What should I investigate?
4. What could I do?
5. What happened after I acted?

## Evidence presentation

AI insight cards should provide a way to inspect:

- underlying posts
- metrics
- comparison period
- detected pattern
- model-generated interpretation

Avoid opaque "AI says..." interfaces.

## Empty states

Empty states should explain what is needed:

- connect account
- import data
- wait for historical observations
- create first goal/experiment

## Loading

Long-running work must have explicit states:

- queued
- running
- completed
- failed
- retrying

## Responsive design

The web application should work across:

- desktop
- laptop
- tablet
- mobile

Desktop is the primary analytics experience; mobile should remain useful for review and planning.
